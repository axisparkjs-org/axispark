`InMemoryRateLimitStore` uses a sliding window counter instead of a sliding log: each bucket keeps the requests of the current and the previous fixed window, so the cost and the memory of a client and handler are constant whatever the limit. It is an approximation of the sliding window: the requests of the previous window are taken as spread evenly over it, and the `retryAfterMs` of a rejected request is the time until the estimate leaves room for one more request.
